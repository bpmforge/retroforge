| D-010 | DSP-1 lifted from enhancement-chip deferral; HLE over LLE (added 2026-09-17, from Brad, tickets W14-18/W14-19) | NON_GOALS #10 deferred all SNES enhancement chips including DSP-1 until plain LoROM/HiROM accuracy was gated; the Phase 14 census (1001/1265 SNES archives render, 0 crashes) met that condition. Super Mario Kart, Pilotwings) moves into scope; SA-1, Super FX, S-DD1, Cx4, ExHiROM, DSP-2/3/4, SPC7110, ST01x stay deferred (FR-CORE-013 diagnostic unchanged). **Decision: HLE of the DSP-1 command set, not LLE of the uPD7725.** Reasons, recorded so this is not re-litigated: (1) the uPD7725's internal program ROM is copyrighted firmware and no dump in the library ships it — law 5 forbids carrying it, and an LLE core would need a user-supplied firmware file with no promise of one; (2) the DSP-1 command set (~30 fixed-point commands: multiply, inverse, sin/cos, rotate, project, etc.) is fully documented publicly and HLE is the approach snes9x has shipped for decades — same accuracy class as this project's other command-level chip work; (3) HLE is deterministic and needs no firmware file, matching the Accuracy Mode honesty contract (the HLE reproduces the chip's *documented* outputs, recorded as an honest limitation, not silently claimed cycle-exact).
