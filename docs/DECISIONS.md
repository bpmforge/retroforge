| D-008 | **Amends D-001** — Alter Ego is freeware, not PD (added 2026-08-16, from Brad, ticket W2-11a) | D-001's parenthetical "Alter Ego (PD)" was wrong on the primary source. `alter_ego/notes.txt`, shipped inside `alter_ego.zip`, says verbatim: *"the game is released as freeware, not Public Domain… I personally grant you rights to do whatever you want with things I created (code, sound effects, graphics), but rights to other components (game concept, characters, title, music) are reserved to authors of these components."* Shiru's own code/SFX/graphics carry do-whatever-you-want terms; concept/characters/title (Denis Grachev) and music (Kulor) are rights-reserved — and the pinned artifact is the whole zip, not Shiru's share of it. **Decision:** both `alter-ego-*` artifacts are reclassified `license_status = "no-license-grant-fetch-only"`, the same posture as every external accuracy oracle. This makes the existing no-vendor/no-rehost rule (TESTING §3, design review G-43) bind: fetch from the author's origin, hash-verify, run; never vendor, mirror or re-host, and `mirrors` stays origin-only. Behaviourally a no-op — that is already how the fixture is used — so it costs nothing and closes a latent hole. Alter Ego **stays** the independent-proof smoke fixture; R-16's "drop it" fallback is unchanged and still human-only. Note the schema has no "freeware, mixed reservations" value; this is the conservative fit, not a legal opinion. |
| D-009 | Local-only ROM verification counts as evidence for a profile (added 2026-09-15, from Brad, tickets W11-06/W14-01) | W11-06 had been blocked since 2026-08-26 on "permitted is not verifiable": Brad's 2026-08-20 ruling allows profiles for commercial titles authored from published documentation, but **law 5 means the repo holds no ROM to check a decode offset against**, so every claim would ship untested — and W9-08 refused exactly that rather than produce a vacuous artifact. Brad supplied a local library (`~/Games/Roms`, 2546 NES+SNES No-Intro archives, outside the repo and never committed) and ruled: **a profile verified only on the developer's own machine IS evidence, provided the profile records the normalized (header-stripped) hash of the ROM it was verified against.** That hash is what makes the claim checkable by anyone holding the same dump, which is what separates this from "someone wrote this down" — the failure mode the ticket's own note named. It does **not** relax law 5 (no ROM bytes in git), FR-PROF-003 (every `memory_map`/`rom_map` entry still carries its source citation), or FR-PROF-006 (facts only, no binary assets). Same evidence-standard class as D-3 (Overload's traces replacing a ROM oracle for W7-18). |
